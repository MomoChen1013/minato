## 二、文章正文

# 還在用 Wix 做網站嗎？找平台做網站後，你不知道的隱藏成本

> **TL;DR**
> - 架站平台的月費不是建置費，是**租金**——網站活著的每一個月都要付，停繳就下線。
> - 五個隱藏成本：功能被綁在方案階層、資產歸屬不清、搬家只能帶走一部分、多語系另外算、效能與 SEO 有天花板。
> - 搬家時帶得走的是網域、文字和圖片；帶不走的是版面、CMS 結構和網址結構——所以搬家的實際成本等於重做一次。
> - 兩年是分水嶺。比價的時候把時間拉到兩年，排名常常會翻過來。
> - 但有三種情況用平台完全合理，文章後半有具體條件。

「Wix 一個月幾百塊就有網站，為什麼你們的報價是幾萬？」

這句話我被問過很多次，而且問得很合理。攤在桌上的兩個數字差距確實很大。

我的回答通常不是講設計。我會請對方把時間軸拉到兩年，然後把幾個沒有寫在方案頁上的東西一項一項加回去。加完之後，那兩個數字有時候還是差很多，有時候會靠得很近——但至少那是同一種單位的比較。

這篇要講的就是那幾項沒有寫在方案頁上的東西。

---

## 平台的價格不是建置費，是租金

**架站平台賣的不是一個網站，是一個網站的使用權。**

這件事影響的是計價的結構。傳統的做法是一次性付一筆建置費，網站是你的；平台的做法是每個月付一筆，網站在平台上。停止付費之後，網站會下線，內容也可能在一段時間後被清掉。

租跟買各有各的道理，但比價的時候不能用「一個月幾百塊」對上「一次幾萬塊」，那不是同一個單位。

**要換算的話，把時間拉到兩年。** 兩年是我建議的分水嶺，因為多數公司的網站至少會用這麼久，而且平台的隱藏成本通常在第二年才會浮出來——第一年還在優惠期、內容還不多、也還沒有人想搬家。

---

## 先把網域、主機、CMS、前端分開看

**很多報價單看起來差很多，是因為上面的名詞不在同一層。** 先把層次拆開，後面的比較才有意義。

- **網域（Domain）**：你的地址，像 `example.com`。向網域註冊商申請，一年幾百到一千多台幣。
- **主機／Hosting**：放網站檔案的地方。共享主機、雲端主機、平台自帶的空間都算。
- **CMS（Content Management System，內容管理系統）**：讓不會寫程式的人自己更新內容的後台。
- **前端**：使用者實際看到的畫面，由 HTML、CSS、JavaScript 組成。
- **DNS**：把網域指到主機的那張對照表，通常在註冊商的後台設定。

架站平台的做法是把這四層包在一起賣，這就是它方便的地方——一個帳號解決全部。也是它綁得最緊的地方，因為要拆開的時候，四層是黏住的。

把層次拆開之後你會發現一件事：換做法很少是整個搬走。網域可以留著，文字內容可以留著，實際換掉的常常只有其中一到兩層。但這件事在平台上比較難成立，原因在下面第三項。

---

## 隱藏成本一：你要的功能綁在方案階層裡

**平台的方案表是照功能切的，而不是照網站大小切的。**

常見會被切在較高方案的項目：

- 移除平台自己的浮水印或網址標記
- 綁定自己的網域
- 表單、電子報、預約功能的進階設定
- 多語系
- 流量、儲存空間、CMS 項目數的上限
- 移除平台廣告

問題不是這些要收錢，是**你通常在做到一半的時候才發現要升級**。第一版做完，發現想加的那個功能在上一階，於是升級；半年後想加多語系，發現又在更上一階。

比較實際的做法：在開始之前先列出「我一定要有的五件事」，然後拿著這五項去官網對照現在的方案表。方案內容與價格會調整，寫在文章裡的數字很快就過期，一定要自己去看當下的版本。

---

## 隱藏成本二：帳號與資產在誰名下

**如果網站是別人幫你開的帳號，那個網站在合約上不一定是你的。**

這件事我每次都會問，而且會問得很直接：如果有一天我們不合作了，這個網站你拿不拿得走？

要確認的有三項：

- **網域註冊在誰名下。** 廠商代買很常見，但續約通知會寄到廠商的信箱，而不是你的。
- **平台帳號是誰開的。** 網站建在廠商的 workspace 底下的話，你的存取權是被授權的，不是擁有的。
- **付款方式綁在誰的卡上。** 這一項決定了斷線的時候誰能救。

三項裡面，網域是最關鍵的。只要網域在你名下，其他部分再麻煩也重建得回來；網域拿不回來，你等於連地址都要換。

我建議把這三項寫進合約，一開始就寫。事後要補的時候通常已經是在不愉快的情境下談了。

---

## 隱藏成本三：搬家的時候，你只能帶走一部分

**離開平台的實際成本，等於重做一次網站。**

帶得走的：

- 網域（前提是註冊在你名下）
- 文字內容（複製貼上就好）
- 圖片素材（要自己一張一張下載）

帶不走的：

- 版面與設計（平台匯出的檔案通常不能直接在別的地方跑）
- CMS 裡的資料結構（文章、產品、分類的欄位設計）
- 平台的內建功能（表單、預約、金流、會員）
- **網址結構**

最後一項是最貴的。平台會用自己的規則產生網址，換到別的地方之後網址對不起來，如果沒有做一對一的 301 轉址，原本累積的搜尋排名會斷掉。內容還在，但 Google 認不得那是同一頁。

所以「以後不滿意再換」這個想法要打個折。技術上換得掉，但你換掉的不只是平台，是三年份的累積。

---

## 隱藏成本四：多語系幾乎都是另外算的

**平台的多語系功能，多半是「同一套版面換字」。**

對只做中英文、而且兩邊內容一樣的網站，這樣就夠了。但如果你要做的是日文版，這個限制會直接撞牆：

- **日文名詞比中文長。** 「聯絡我們」變成「お問い合わせ」，導覽列和按鈕的寬度會不夠。同一套版面的話，中文版排得剛剛好的地方，日文版就會擠出來。
- **斷行與行高的預設值是英文邏輯。** 日文有行尾禁則，標點和小字不能出現在行首，這需要另外設定。
- **區塊順序常常需要不一樣。** 日本 B2B 訪客習慣先看会社概要再看服務，中文版的順序照搬過去不見得合適。
- **第二語言的頁面有沒有被正確索引**，平台的可控程度有限。

進日本市場的案子，多語系這一項的重要性通常會排到前三名。相關的規劃我寫在〈[中日雙語網站怎麼規劃？](/blog/chinese-japanese-bilingual-website)〉和〈[台灣企業進日本市場，網站需要準備什麼？](/blog/japan-market-website-checklist)〉。

## 隱藏成本五：效能與 SEO 的天花板

**平台不會讓你的網站做不了 SEO，但它會限制你能調到多細。**

實務上常遇到的幾個限制：

- 平台會載入自己的 script 與樣式表，你拿不掉，載入速度有一個下限
- 可以自訂的 `<head>` 內容有限，結構化資料（JSON-LD）能放到多完整要看方案
- 網址結構的自由度低，有些平台會強制在網址裡加固定的路徑片段
- hreflang 的設定通常包在多語系功能裡，不能單獨處理
- 圖片壓縮、快取這些效能項目由平台決定

這些對「有一個能被搜尋到的公司介紹」來說影響不大。但如果你的策略是靠內容和 SEO 帶來詢問，天花板會在第二年變成很實際的問題——你已經寫了三十篇文章，卻改不了它們的網址結構。

順帶提醒一件事：漂亮跟被找到是兩回事，被找到跟有人詢問又是另外一回事。這三件事會卡在不同的地方，換平台只能解決其中一件（有時候一件都解決不了）。這一層我寫在〈[網站很漂亮，為什麼卻沒有人詢問？](/blog/beautiful-website-no-inquiry)〉。

## 那什麼時候用平台是對的？

**三種情況我會直接建議用平台，不用找設計師。**

**一、你在驗證一個還沒確定的生意。** 產品還沒定案、客戶輪廓還在調整，這個階段網站的任務是「先有」，不是「做對」。花三個月做一個精緻的網站，然後兩個月後方向轉了，那筆錢就沒了。

**二、單次活動或短期用途。** 展會頁、報名頁、活動 landing，用完就收。這種需求不需要考慮兩年後的事。

**三、內容天天改，而且沒有人可以幫你改。** 每天更新的營業資訊、菜單、庫存，找設計師每次都要來回，成本反而更高。

還有一種混合的做法值得考慮：**主網站自己掌握，短期活動頁用平台。** 兩邊的優勢都拿得到，只要網域和主要的搜尋累積留在你自己這邊。

## 決定之前，把兩年攤開來算一次

把下面這幾項填一遍，答案通常就出來了：

| 項目 | 平台方案 | 客製做法 |
| --- | --- | --- |
| 第一年總支出 | 月費 × 12 ＋ 升級費 ＋ 設定工時 | 建置費 ＋ 網域 ＋ 主機 |
| 第二年總支出 | 月費 × 12 ＋ 可能的方案調漲 | 網域 ＋ 主機 ＋ 維護 |
| 我一定要的五個功能在哪一階？ | | |
| 網域註冊在誰名下？ | | |
| 兩年後想搬家，帶得走什麼？ | | |
| 需要日文或英文版嗎？額外多少？ | | |
| 誰負責更新，一個月幾次？ | | |

最後一列其實是整張表最重要的一題。如果答案是「沒有人」，那你買的後台不會有人登入，每個月的方案費是在付一個用不到的能力。如果答案是「行銷每週都在調」，那平台的月費很划算，因為它省下來的是等工程師的時間。

## 常見問題

**Q1. Wix 做的網站可以搬走嗎？**
網域和文字內容可以帶走，版面、CMS 結構與平台內建功能通常帶不走。最大的風險是網址結構改變後原有的搜尋排名會斷掉，需要做一對一的 301 轉址。實務上「搬家」的成本接近重做一次。

**Q2. 用架站平台做的網站對 SEO 不好嗎？**
不會不能做，但可調整的範圍有限。平台自帶的 script 會影響載入速度，`<head>` 的自訂程度、網址結構與結構化資料的完整度通常受方案限制。基本的公司介紹網站影響不大，靠內容做 SEO 的策略會碰到天花板。

**Q3. 公司網站可以自己做嗎？**
可以。三到五頁的公司介紹用現成工具自己做完全合理。會需要找設計師，通常是因為需要的不只是頁面，而是決定要放什麼、順序怎麼排、要讓訪客做什麼動作。

**Q4. 網域一定要自己買嗎？**
建議自己買、註冊在公司名下。廠商代買很常見，但續約通知會寄到對方的信箱，合作結束時的交接也會多一道手續。網域是所有網站資產裡最關鍵的一項。

**Q5. 多語系網站適合用平台做嗎？**
內容一致、版面可以共用的話可以。如果各語系的區塊順序、內容深度或 CTA 需要不同（進日本市場的案子多半是這樣），平台的多語系功能通常不夠用，因為它的預設是同一套版面換字。
