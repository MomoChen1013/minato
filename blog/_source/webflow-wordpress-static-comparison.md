## 二、文章正文

# 企業官網要用 Webflow、WordPress，還是自己開發？中小企業網站架構怎麼選

> **TL;DR**
> - 決定平台的是三個問題：**誰維護、多久更新一次、兩年後會不會長出新東西**。
> - 內容幾乎不動、要求速度和多語系可控 → **靜態網站**。
> - 行銷或設計人員要自己改版面、不只是改文字 → **Webflow**。
> - 文章、商品、會員、複雜分類一直長 → **WordPress**。
> - 比價的時候把「兩年」放進去算，第一年最貴的方案第三年常常最便宜。

我自己的工作室網站是純手寫的 HTML、CSS 跟一點 vanilla JS，放在 GitHub Pages 上，網域從 Namecheap 指過來。講出來偶爾會被問：你不是做設計的嗎，怎麼不用 Webflow？

我的理由很普通。這個站一個月大概改兩到三次，改的都是文字和新文章，改的人從頭到尾只有我一個。為了這個需求去養一個 CMS、每個月付方案費，我自己會覺得怪。

「網站要用什麼做？」通常是企業開始找設計公司之後問的第一個問題。我後來發現它不好回答，因為問題本身預設了有一個「比較好的平台」。真正會決定答案的是另外三件事：這個網站誰要維護、多久更新一次、兩年後會不會長出新東西。

---

## 網域、主機、CMS、前端，其實是四件不同的事

**很多報價單看起來差很多，是因為上面那幾個名詞不在同一層。** 先把層次拆開，後面的比較才有意義。

- **網域（Domain）**：你的地址，像 `example.com`。在 Namecheap、Gandi、Cloudflare 這類註冊商買，一年幾百到一千多台幣。
- **主機／Hosting**：放網站檔案的地方。共享主機、雲端主機、GitHub Pages、Cloudflare Pages 都算。
- **CMS（Content Management System，內容管理系統）**：讓不會寫程式的人自己更新內容的後台。WordPress 是 CMS，Webflow 內建 CMS，靜態網站預設沒有。
- **前端**：使用者實際看到的畫面，由 HTML、CSS、JavaScript 組成。
- **DNS**：把網域指到主機的那張對照表，通常在註冊商後台改。

我自己的站，網域在 Namecheap、檔案在 GitHub Pages、DNS 記錄在 Namecheap 設定、沒有 CMS、前端我自己寫。四層東西分散在三個地方。所以有人問我「網站放在哪裡」的時候，我會先確認他問的是哪一層。

把四層拆開之後你會發現，換平台很少是整個搬走，多數時候動到的只有其中一到兩層。網域可以留著，內容可以留著，換掉的常常只有前端跟主機。

---

## WordPress 適合什麼樣的企業？

**WordPress 適合內容量會持續增加、而且要由公司內部的人自己更新的網站。** 它的市占率長年是所有 CMS 裡最高的，代表你要找人接手、找外掛、找教學都相對容易。

它的強項很明確：

- 後台編輯，行銷人員可以自己發文章、換 banner、開活動頁
- 外掛生態成熟，表單、SEO、金流、會員大多有現成方案
- 部落格與文章分類的架構是原生的，不用另外做
- 多語系可以靠 WPML 或 Polylang 這類外掛處理

要付的代價也很明確，而且是每個月的：

- 主機、WordPress 核心、佈景主題、外掛，四層都要更新
- 外掛之間會衝突，尤其是版型類的外掛加上頁面編輯器
- 安全性問題大多不是 WordPress 本身，是停留在舊版本的外掛
- 裝到十幾個外掛之後，載入速度會很明顯地掉下來

我看過的 WordPress 網站，狀況大概分成兩種。一種是行銷團隊一週發兩三篇文章，後台每天有人登入，工具跟需求完全對得上。另一種是三年前做好之後就沒有人再進去過，外掛停在很舊的版本，連後台密碼都要找很久（通常最後是在某個離職同事的交接文件裡）。

所以決定用 WordPress 之前，我會建議先確認一件事：公司裡有沒有一個人的工作內容，實際包含「每個月登入後台按更新」。沒有的話，維護成本會在第二年、第三年變成問題。

---

## Webflow 適合什麼樣的企業？

**Webflow 適合有行銷或設計人力、需要自己調整版面而不只是改文字的品牌官網。** 它是視覺化的網站建置工具，拉版面的同時直接產生 HTML 和 CSS，內建 CMS、hosting 跟 CDN。

適合的情境很集中：品牌官網、產品行銷頁、活動 landing page、需要頻繁改版面測試轉換率的網站。

要注意的地方有幾個，簽約前值得一項一項確認：

- **費用是月費或年費**，網站活著就要一直付，停繳網站就下線
- **匯出的程式碼不包含 CMS**，CMS 裡的內容和動態綁在平台上
- **CMS 項目數上限跟方案綁在一起**，這個數字官方會調整，簽之前自己去官網看一次現在的數字
- **中文和日文的字體、字距、斷行**要另外處理，預設值是照英文排版邏輯來的
- **帳號歸屬**：如果是設計公司幫你開的專案，網站在誰的 workspace 底下？

最後那一項我每次都會問，而且會問得很直接：如果有一天我們不合作了，這個網站你拿不拿得走？

Webflow 的平台依賴要標價。你用月費和資產歸屬，換到的是行銷人員不用找工程師就能改版面的能力。對一個每季都在測試新 landing page 的團隊，這筆交換很划算；對一個官網三年不動的公司，就是在付一個用不到的能力。

---

## 靜態網站適合什麼樣的企業？

**內容結構穩定、更新頻率低、對載入速度和多語系有要求的公司，靜態網站的兩年總成本通常最低。** 靜態網站的意思是頁面在上線前就已經產生好，使用者連進來時伺服器直接把檔案給他，中間沒有資料庫查詢。

實際的流程長這樣：

```text
Figma
  ↓  介面設計定稿
HTML / CSS / JS
  ↓  切版與互動
Git
  ↓  版本控制
Cloudflare Pages / Firebase Hosting / GitHub Pages
  ↓  部署
Custom Domain
```

它省下來的東西是連鎖的。沒有資料庫，就沒有資料庫效能問題；沒有外掛，就沒有外掛衝突；沒有後台登入頁，就少掉一個最常見的被攻擊入口。

我自己的站就是這樣跑的。表單交給 Web3Forms 用 AJAX 送出，加一個 honeypot 欄位擋機器人；GA4 開一個獨立的 property 追表單送出、LINE 點擊和預約點擊。要新增一篇文章，我就是複製文章模板、換內容、commit、推上去。

多語系是靜態網站我最喜歡的一段。日文版和英文版就是各自的資料夾，`/ja/`、`/en/`，加上 hreflang 標籤互相指認。因為每個語系的頁面是獨立的檔案，日文版可以有跟中文版不一樣的區塊順序、不一樣的行高、不一樣的 CTA 文案，不用被同一個模板綁死。用外掛做多語系的時候，這件事會麻煩很多。

代價只有一個，但很實際：客戶自己不能改。要嘛回來找我，要嘛接一個 headless CMS 進去，那就是另一筆預算了。

---

## 三種做法的成本怎麼比較？

|              | WordPress | Webflow | 靜態網站 |
| ------------ | --------- | ------- | ---- |
| 初期建置成本       | 中         | 中       | 中偏低  |
| 每月固定費用       | 主機＋外掛授權   | 平台方案費   | 幾乎為零 |
| 設計自由度        | 高         | 高       | 非常高  |
| CMS（客戶自己更新）  | ★★★★★     | ★★★★    | △    |
| 維護心力         | 高         | 低       | 很低   |
| 載入效能         | △         | ○       | ◎    |
| 多語系          | 靠外掛       | 平台功能，另計 | 完全可控 |
| 資產可攜性        | 高         | 中       | 高    |
| 適合的更新頻率      | 每週        | 每月      | 每季   |

比價的時候，我會建議把時間拉到兩年。第一年報價最低的方案，加上第二年的外掛授權、主機續約、改版工時之後，排名常常會翻過來。

順帶講一下報價這件事。同樣是「靜態網站」，套現成模板改字，跟從資訊架構重新開始，中間差的不是切版工時。我自己的報價是基本費加上頁數計價，基本費付掉的是資訊架構、內容整理和一套之後可以繼續長出新頁面的版型系統。首頁那張視覺是最後才發生的事。

## 如果你是中小企業，我會怎麼選？

先回到最前面那三個問題，然後對照下面的情境：

**內容一年更新一到兩次、主要功能是介紹公司和服務、希望載入快 → 靜態網站。**
公司介紹、服務說明、品牌官網、單頁 landing page 都在這一區。做完之後幾乎不用管它。

**行銷或企劃人員要自己改版面、每季都在調 landing page → Webflow。**
前提是公司裡真的有這個人，而且他有時間學工具。沒有這個人的話，你買到的是一個沒人用的後台加上每個月的帳單。

**文章、商品、案例、會員這些資料會一直長，而且要分類、要搜尋 → WordPress。**
內容型網站、媒體、要開部落格認真做 SEO 的公司，用 WordPress 的效益會回來。

**要做多語系 → 先決定語系之間可不可以長得不一樣。**
如果日文版只是中文版的翻譯，三種做法都行。如果日文版的區塊順序、內容深度、CTA 要跟中文版不同（多數進日本市場的案子都是這樣），靜態網站最好處理。

還有一種狀況：你已經有網站了，只是覺得不好用。這時候先不要急著整站重做。我會先看流量進來之後停在哪一頁、從哪一頁離開，很多時候問題出在資訊架構和文案，換平台解決不了，重做一次只是把同樣的問題換一個比較漂亮的樣子。

## 常見問題

**Q1. 公司網站架設費用大概多少？**
台灣市場的落差很大，從幾萬到幾十萬都有。差異主要不在切版，在於有沒有做資訊架構、文案整理、原創設計，以及是否包含多語系。看報價的時候把「這筆錢買到哪幾層」問清楚，比單純比總價有用。

**Q2. 公司網站可以自己做嗎？**
可以。如果你的需求是三到五頁的公司介紹，用現成工具自己做完全合理。會需要找設計師，通常是因為你需要的不只是頁面，而是想清楚要放什麼、順序怎麼排、要讓訪客做什麼動作。

**Q3. Webflow 做的網站可以搬走嗎？**
可以匯出 HTML、CSS、JS，但 CMS 的內容和動態功能不會跟著出來。如果之後可能要搬家，建議在專案一開始就確認網站建在誰的帳號底下，並寫進合約。

**Q4. 靜態網站對 SEO 不利嗎？**
不會。搜尋引擎看的是 HTML 結構、內容品質、載入速度和行動裝置體驗，靜態網站在速度這一項通常最有優勢。要注意的是 meta 標籤、結構化資料和 sitemap 要自己補完整。

**Q5. 多語系網站要用哪一種？**
如果各語系內容一致，三種都可以。如果各語系的資訊架構需要不同，靜態網站或多站台架構最好控制。用外掛做多語系時，最常卡住的是版面在切換語言後跑掉，以及第二語言的頁面沒有被正確索引。

---

如果你正在報價階段，卡的不是設計而是「到底該走哪一條路」，可以把三件事寫給我：**這個網站誰負責更新、多久更新一次、需不需要日文或英文版**。這三個答案通常就能把選項砍到剩一個。

我這邊有一份免費的 fit call，20 到 30 分鐘，只釐清範圍不做解決方案，講完你自己去發包也完全沒問題。LINE 或表單都可以找到我。
